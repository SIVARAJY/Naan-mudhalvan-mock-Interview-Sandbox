# Supabase database setup

1. Create a Supabase project.
2. Open SQL Editor and run:

```sql
create table if not exists public.attempts (
  id bigint generated by default as identity primary key,
  student_name text not null,
  attempt_type text not null,
  topic text not null,
  score double precision not null check (score >= 0 and score <= 100),
  feedback text not null,
  created_at timestamptz not null default now()
);

alter table public.attempts enable row level security;
revoke all on table public.attempts from anon, authenticated;
```

This prototype connects from the Flask server using a PostgreSQL connection string, so browser-side Supabase keys are not needed. Do not put the database password or a Supabase secret/service-role key in HTML/JavaScript or commit it to GitHub. The app's server-side database connection uses the database credentials, so protect the `.env` file.

3. In Supabase, click **Connect** and copy the PostgreSQL connection string. Prefer the **Session pooler** connection if your network does not support direct IPv6 connections. Use the exact host, username, and port Supabase gives you; do not guess the pooler host. URL-encode special characters in your database password if needed.
4. Copy `.env.example` to a file named `.env`. Put your real connection string in `DATABASE_URL`.
5. Install and run:

```bat
py -m venv .venv
.venv\Scripts\activate
py -m pip install -r requirements.txt
py app.py
```

6. Visit `http://127.0.0.1:5000`. `app.py` creates the `attempts` table if it does not exist and saves submissions to Supabase.

## Security note
This academic prototype uses server-side database credentials. Never expose those credentials in frontend code or share them in screenshots. For a production deployment, add authentication and per-student authorization before allowing access to personal attempt history. RLS is enabled and direct browser roles are revoked in the SQL above; the trusted Flask backend connects directly to PostgreSQL.
